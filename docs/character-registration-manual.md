# 武将登録・検証マニュアル(運用ドキュメント)

このファイルはサイトのコンテンツではなく、data-writer/kanshi-yaku系エージェントが武将登録・検証作業を行う際に参照する内部運用マニュアル。git管理下に置き、worktreeでの並列作業・マージを通じて全エージェントに反映される。

体制:
- **管理エージェント**: ユーザーとエージェント群の仲介役(メインセッション)。全体の進行管理・worktreeマージ・作業の割り振りを行う。
- **秘書エージェント**: 管理エージェント専属の常駐アシスタント。ユーザーからの雑務、作業エージェントからの報告の調整、問題発生時のこのマニュアルの検証・更新を担当。手が空いている時は待機(何もしない)。
- **作業エージェント**: 実際の武将登録・検証を行う。作業中に詰まった点・気づいた点をこのマニュアルに追記する。

追記ルール: 新しい手順や注意点を見つけたら、該当セクションに追記する。既存の記述を消さず、日付付きで追記していく。工数(所要時間・ツール呼び出し回数の目安)も必ず記録する — 管理エージェントがこの実績を元にチャンク分割の重みを決めるため。

## A. 既存武将の検証(青丸→黄色丸)手順

1. `characters.html` または `characters-kyoku.html` の該当武将エントリを読む。
2. `assets/img/characters/no{No}_full.png` を開き、名前/No./コスト/攻撃・防御・兵法の基礎値と成長値/lv0Troops/rankGrades(4隅のバッジ)/初期スキル名/スキル詳細文を目視照合する。
   - **要注意**: rankGradesのyumi(弓)/uma(馬)フィールドが入れ替わって登録されているケースが頻発している(2026-07-30、複数チャンクで発見)。カードの4隅のバッジ配置(左上=槍、右上=馬、左下=弓、右下=器)を必ず再確認すること。
   - 虹色/レインボーの"X"バッジを"A"と誤読するケースがあるので拡大して確認する。
3. ixanary.comの生HTML(`curl`、WebFetchの要約は使わない)でTR1〜TR6のデータが実際に存在するか確認し、不足があれば追記する。
4. 無尽/撤退/覇道/不屈/飛翔/兵站/人数依存(防御参加武将数)のキーワードを持つスキルは、対応するskills-*.html一覧ページに登録されているか確認する(未登録なら追加、categoryLinksも双方向に張る)。
5. 上記すべて確認・修正できたら`reviewedOk:true`を設定する。
6. synthesisTable(合成候補)の追加は対象外(別工程)。

**工数実績(目安・2026-07-30時点):**
- TRなし/LV10のみで完結するスキルの武将: 1体あたり数分程度(画像照合+ixanary確認1回)。天チャンクD(21体、大半がTRなし)が約37分で完走。
- TR1〜TR6まであるスキルの武将: ixanary生HTMLの照合に手間がかかり、1体あたりの所要時間が数倍に伸びる。
- **重要な失敗パターン(2026-07-30)**: エージェントが「担当分を全部調査してから最後にまとめて編集」という進め方をすると、編集フェーズに入る前に中断された場合、それまでの調査がすべて無駄になる。**1体の検証・修正が確定したら、次の武将に進む前に必ずその場で`reviewedOk`付与+`git commit`まで終わらせること。** これを徹底しなかったチャンクは30分以上動いても差分ゼロのまま終わった実績がある。

## C. 過去の失敗パターン集(参照)

- rankGrades誤読(X/レインボーバッジをAと誤読、弓/馬フィールド入れ替え) — 必ず画像を拡大確認。
- 「調査完了後にまとめて編集」による中断時の全損 — 1体ごとに即commit。
- 均等な頭数分割はスキルの複雑さのばらつきを無視しており、チャンク間で完了速度に数倍の差が出る。

**2026-07-30追記(1245/1249/1254/1258/1263/1267/1271/1215/1204/1208/1212検証時に判明):**

- **PowerShellスクリプトを`-File`で実行する際は必ず`-ExecutionPolicy Bypass`を付ける。** `powershell -NoProfile -File script.ps1`だけだと環境によってはUnauthorizedAccess(実行ポリシー)エラーで落ちる。`powershell -NoProfile -ExecutionPolicy Bypass -File script.ps1`にすること。
- **rankGradesの誤りはyumi/uma入れ替えだけではない。** 今回、yari・umaの2つが揃って正しい値(S)から'A'に落とされ、代わりにki(器)またはyumi(弓)いずれか1箇所に本来無いはずのS/SS/X等の高ランクが乗っている、というパターンが複数の武将(1245・1249・1258・1271)で見つかった。4隅とも思い込みで確認せず、必ず4バッジ全てを個別にズームして読み直すこと。
- **カード上のスキル名の一部漢字が装飾フォントで誤読しやすい。** 「蟲砲」→正しくは「轟砲」(1249)、「義陣蟄野」→正しくは「義陣響野」(1258)、「義睿鉄心」→正しくは「義響鉄心」(1267)、という誤字が既存データに複数見つかった。**スキル名は画像の目視だけで確定せず、`https://ixanary.com/cards/{No}/`の生HTMLから`skills/`を含むリンク(`grep -o "skills/[^\"&]*"`)を取得して正式名称と突き合わせる。**
- **trTableのLV10行の確率(baseRate)がLV1の値を誤って転記しているケースがある。** 1263(徳川家康 覇5)は「確率16%」と登録されていたが、ixanary生HTMLではLV10〜TR5は全て「確率+50%」でLV1のみ+16%だった。ixanary生HTMLの`<th>LV10</th>`直後の値を必ずLV1と読み違えないよう`<th>`タグ単位で区切って確認すること。
- **スキル効果文の否定/条件表現(「〜を除く」「〜のみ」)は意味が反転しやすいので原文を一字一句読む。** 1254(六角承禎)は「自領の加勢戦闘時を除く」と登録されていたが、実際のカード文は「自領以外の加勢戦闘時のみ」であり、適用条件が実質逆(自領防衛では発動せず、他家への加勢でのみ発動)だった。要約や記憶で意訳せず、原文をそのまま読んでから日本語を整えること。
- **飛翔N付与スキルは「飛翔Nを持つ」だけで終わらせず、括弧内の補足効果まで読む。** 1212(九鬼嘉隆)は「飛翔4」に「敵軍に飛翔を持つ武将が4人未満のとき通常武将ダメージを受けない」という条件付き効果が付随しており、この部分が抜けていた。飛翔値の数字だけでなく、その後に続く括弧書きの説明文まで必ずカード原文で確認する。
- **模倣不可の独立行違反([[feedback_skilldetail_prose_format]])は既存データにも多数残っている。** 今回検証した11体のうち5体で「(模倣不可・TR1〜TR5は未確認)」のように既存の効果文末尾に模倣不可を紛れ込ませる誤りが見つかった。検証対象武将のskillDetailを読むたび、「模倣不可」の文字列が①の前に独立行として存在するか必ずチェックする。
- **「TR1〜TR5は未確認」という注記は、ixanary生HTMLで実際にTR列が存在しないことを確認できたら削除する。** 「未確認」のまま放置せず、確認の結果TRが存在しないと判明したなら断定的な記述に直すか注記自体を削る(存在した場合はもちろん値を追記する)。今回11体中6体でTRが実在せず(LV1/LV10のみ)、残り2体でTR1〜TR5が実在し追記が必要だった。
